DTG 의무 장착 제도

교통안전법 제55조에 의거 사업용 화물차에 DTG(Digital Tachograph) 의무 장착. 2024년 10월부터 총중량 25톤 이상으로 의무제출 범위 확대(교통안전법 제56조). 국토교통부 산하 한국교통안전공단이 eTAS로 분석 결과를 제공.

eTAS의 구조적 한계

핵심 문제

현행 eTAS 출력: "60km/h 초과 과속 9회, 급가속 3회, 급진로변경 2회"

→ 9회 중 몇 회가 범칙금(행정)인지, 형사처벌 대상인지, 제151조의2 반복과속인지 알 수 없음

→ 법적 심각도 해석 없음 = 운수회사 법적 리스크 관리 불가

과속 법적 심각도 6단계 (SGT 기준)

교통법령 온톨로지 설계

IRAC 구조 반영 · 7개 클래스 · 6개 관계

클래스 체계

HazardousBehavior LegalArticle SeverityLevel Penalty AggravatingFactor VehicleType RoadType
클래스설명주요 속성인스턴스 예시
HazardousBehavior위험운전 유형 (11대)name, threshold, unitspeeding, sudden_accel, sudden_decel ...
LegalArticle법령 조문 단위id, law, jo_num, title, content, typeRTA_17 (제17조), RTA_154 (제154조)
SeverityLevel과속 심각도 6단계id, label, speed_over_min, speed_over_max, criminallevel_1 (0~20), level_5 (80~100)
Penalty처벌 내용id, type, value, vehicle, criminalFINE_L4_FREIGHT (13만원), P_CRIMINAL_154
AggravatingFactor가중처벌 조건id, name, legal_basisschool_zone, repeat_100km

관계(Edge) 유형

// IRAC 구조를 반영한 법령 관계 (Neo4j Property Graph) HazardousBehavior -[:VIOLATES]→ LegalArticle // 위반행위 → 위반 조문 LegalArticle -[:RELATED_TO]→ LegalArticle // 정의조문 → 벌칙조문 LegalArticle -[:DEFINED_BY]→ LegalArticle // 조문 → 정의 조문 SeverityLevel -[:PENALIZED_BY]→ Penalty // 심각도 → 처벌 내용 AggravatingFactor -[:AGGRAVATES]→ SeverityLevel // 가중조건 → 등급 상향 SeverityLevel -[:ESCALATES_TO]→ SeverityLevel // 반복과속 → 상위 등급

IRAC 구조와의 대응

IRAC 단계대응 클래스/관계담당 에이전트
I (Issue · 쟁점)HazardousBehavior 식별, 속도 계산I-Agent
R (Rule · 법규)VIOLATES → LegalArticle → RELATED_TO 경로 탐색R-Agent (KG 쿼리)
A (Application · 포섭)SeverityLevel PENALIZED_BY Penalty + AggravatingFactorA-Agent
C (Conclusion · 결론)최종 심각도 + 인용 조문 + 처벌 내용C-Agent
— (Verification · 검증)Citation 교차확인, KG 일관성 검증V-Agent
설계 원칙

OWL 기반 형식 온톨로지는 구축 비용이 높고 법령 개정 시 유지관리 부담이 크므로, 본 연구는 Neo4j의 Property Graph Ontology를 채택. 실용적 법적 추론 지원에 최적화.

핵심 Cypher 쿼리

// 1-hop: 위반유형 → 관련 조문 검색 (R-Agent) MATCH (h:HazardousBehavior {name: $violation_type}) -[:VIOLATES]->(a:LegalArticle) RETURN a.id, a.jo_num, a.title, a.content ORDER BY a.id // 2-hop: 위반 → 정의조문 → 벌칙조문 (Multi-hop) MATCH (h:HazardousBehavior {name: $vtype}) -[:VIOLATES]->(a:LegalArticle) -[:RELATED_TO]->(a2:LegalArticle) RETURN DISTINCT a2.id, a2.jo_num, a2.content // 초과속도 → SeverityLevel 직접 조회 (R-Agent) MATCH (s:SeverityLevel) WHERE s.speed_over_min <= $speed_over AND s.speed_over_max > $speed_over OPTIONAL MATCH (s)-[:PENALIZED_BY]->(p:Penalty) RETURN s.id, s.label, s.criminal, s.legal_basis, collect(p.value) // 가중조건 조회 (어린이보호구역 시) MATCH (af:AggravatingFactor) RETURN af.name, af.description, af.legal_basis // 별표 기준표 전체 조회 (S3 컨텍스트 제공) MATCH (a:LegalArticle) WHERE a.type = 'penalty_table' RETURN a.id, a.jo_num, a.title, a.content

07 · Multi-hop

Multi-hop 추론 원리

경로 탐색 · M6 Recall 정의 · S2↔S3 증거

Multi-hop이란

단일 검색(single-hop): 쿼리 → 관련 노드 (1단계)

Multi-hop: 쿼리 → 중간 노드 → 최종 노드 (2단계 이상) — 법률 도메인에서 "위반행위 → 정의조문 → 벌칙조문"처럼 여러 노드를 거쳐야 완전한 법적 추론이 가능하다.

교통법령 Multi-hop 경로 예시

// 과속(speeding) 위반의 Multi-hop 경로 // Hop 1: 위반 → 정의조문 speeding ─[:VIOLATES]→ RTA_17 (제17조: 자동차등의 속도) // Hop 2: 정의조문 → 벌칙조문 RTA_17 ─[:RELATED_TO]→ RTA_156 (제156조: 20만원 이하 — level_1~4) RTA_17 ─[:RELATED_TO]→ RTA_154 (제154조: 30만원 이하 — level_5, 80km/h 초과) RTA_17 ─[:RELATED_TO]→ RTA_153 (제153조: 100만원 이하 — level_6, 100km/h 초과) // Hop 3 (조건부): 벌칙조문 → 가중조항 RTA_154 ─[:RELATED_TO]→ RTA_151_2 (제151조의2: 반복과속 3회 이상 → 가중)

M6 Multi-hop Recall 계산 방법

# 필수 조문 집합 정의 (VIOLATION_MAPPING 기반) required = {"RTA_17", # 정의: 속도제한 "RTA_156"} # 벌칙: 20만원 이하 (level_1~4의 경우) # 어린이보호구역 포함 시 required.add("RTA_12") # Recall 계산 recall = len(cited_articles ∩ required) / len(required) # 결과 비교: # S1: 0.0% — 인용 없음 (환각 100%) # S2: 0.0% — Flat RAG로는 경로 추론 불가 # S3: 62.5% — KG Multi-hop으로 연결 가능 # S4: 80.0% — 멀티에이전트로 추가 경로 탐색

S2↔S3 비교: Multi-hop의 핵심 증거

논문 핵심 주장

S2→S3 Multi-hop Recall: 0% → 62.5% (+62.5%p)

동일 코퍼스에서 Flat RAG는 Multi-hop 경로 추론 불가. KG가 "위반→정의→벌칙" 관계를 구조적으로 제공할 때 비로소 완전한 법적 추론 사슬이 구성된다. Severity F1 차이(+7.2%p)보다 Multi-hop Recall 차이(+62.5%p)가 훨씬 크다는 점이 KG 효용의 본질을 보여준다.

StageMulti-hop Recall이유
S1: Vanilla0.0%인용 없음, 환각 100%
S2: Flat RAG0.0%청크 유사도 검색으로 관계 경로 추론 불가
S3: GraphRAG62.5%KG VIOLATES→RELATED_TO 경로 제공
S4: IRAC-V80.0%R-Agent가 멀티홉 + API Fallback으로 추가 경로 탐색

Bug B 수정 — I-Agent speed_over 계산

버그 원인 (v3 이전)

I-Agent 프롬프트에 "화물차(4톤 초과) 법정 제한속도: 고속도로 80km/h" 구절 포함 시, 도로 제한속도가 80km/h 미만(50/60km/h)일 때 LLM이 차종 보정값 +10km/h를 오적용함. 초과속도 70→80, 78→88, 90→100, 98→108km/h로 과산정 → 상위 등급 오판정.

## v4 수정: Python에서 직접 계산 (LLM에게 맡기지 않음) def _calc_speed_over(scenario): pre_calc = scenario.get('speed_over') # 시나리오 JSON 우선 if pre_calc is not None: return max(0, int(pre_calc)) actual = scenario.get('actual_speed', 0) limit = scenario.get('speed_limit', 0) return max(0, int(actual) - int(limit)) ## I-Agent 프롬프트 핵심 변경 prompt = f""" [DTG 계측값] 실제속도: {actual}km/h, 제한속도: {limit}km/h 초과속도: {speed_over}km/h ← 이 값을 speed_over_km에 사용 (초과속도 = 실제속도 - 도로 제한속도, 차종 보정 없음) """ ## 안전장치: LLM이 값을 바꿨을 경우 강제 복원 for issue in result['issues']: if issue.get('issue_type') == 'speeding': issue['speed_over_km'] = speed_over # 강제 복원

Self-Healing 메커니즘

V-Agent가 "KG 불일치" 또는 "판정 실패" 오류 감지 시 → I-Agent 결과는 유지하고 R→A→V 순서로 최대 2회 재시도 → 재시도 후에도 unknown/undetermined이면 첫 번째 결과 복원.

속도 맵매칭 (SpeedLimitMatcher)

단계소스방법샘플 커버리지
1단계전국도로안전표지 표준데이터GPS 반경 500m 최근접 표지판0% (GPS 좌표 오차)
2단계한국도로공사 고속도로 구간노선명+구간 텍스트 매칭0% (고속도로 전용)
3단계 (fallback)시행규칙 제19조 법정속도도로유형별 기본속도 적용100%
4단계 (보정)차종 규정화물차(1.5톤 초과) 고속도로 80km/h 상한자동 적용

샘플 데이터 100% fallback은 Limitation에 명기 필요. 전체 데이터에서의 매칭률 측정 권장.

def bootstrap_ci(y_true, y_pred, metric_fn, n_boot=2000, seed=42): np.random.seed(seed) n = len(y_true); scores = [] for _ in range(n_boot): idx = np.random.choice(n, n, replace=True) scores.append(metric_fn([y_true[i] for i in idx], [y_pred[i] for i in idx])) mean = np.mean(scores) lo = np.percentile(scores, 2.5) hi = np.percentile(scores, 97.5) return mean, lo, hi ## 논문 표기: 82.3% [76.1%, 87.9%]

McNemar Test (연속성 보정)

## 쌍별 비교: S3 vs S4 S3_correct = [yt == yp for yt, yp in zip(y_true, S3_preds)] S4_correct = [yt == yp for yt, yp in zip(y_true, S4_preds)] b01 = sum(1 for a, b in zip(S3_correct, S4_correct) if not a and b) b10 = sum(1 for a, b in zip(S3_correct, S4_correct) if a and not b) ## 연속성 보정 적용 chi2 = (abs(b01 - b10) - 1)**2 / (b01 + b10) p = 1 - scipy.stats.chi2.cdf(chi2, df=1) ## S3→S4: b01 >> b10이면 p<0.05 → 유의미한 개선
